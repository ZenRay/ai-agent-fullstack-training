# 客户端设计

CLI 和 Web 共用同一套事件帧、同一次 `reduce` 和同一组命令。两边的差别在传输限制和怎么把 `View` 画出来。停止必须是单独的取消请求。刷新或断线只结束本地阅读。

依据：

- [AG-UI：客户端模型](https://docs.ag-ui.com/introduction)
- [fetch 版 SSE](https://www.server-sent-events.com/frontend-consumption-client-patterns/fetch-based-sse-clients/)
- [Vercel AI SDK：abort 与可恢复流](https://ai-sdk.dev/docs/troubleshooting/abort-breaks-resumable-streams)
- [Clusto：按序号恢复](https://clusto.app/docs/transport)
- [agentctl：CLI 的输出模式](https://github.com/opensourceops/agentctl/blob/main/docs/guides/DURABLE_STREAMING.md)

## 概念

客户端是运行日志的一个阅读者。事实在 Run Store 里。客户端做三件事：

1. 发命令：创建这次 run，或取消它。
2. 把 SSE 帧解成 `RunEvent`，按 `seq` 折进同一个 `View`。
3. 把 `View` 画出来。CLI 打成文本，Web 画成消息和工具卡片。

`View` 里有运行状态、已闭合和正在生成的消息、按 `call_id` 拼好的工具、用量、错误和最后序号。重复到达的序号直接丢掉。投影规则见 `docs/02-RunEvent设计.md`。

## 它解决什么

- 创建运行是 POST 加 JSON 正文。浏览器的 `EventSource` 只能 GET，也不能加 `Authorization`。创建这条流两边都用带正文的 HTTP 客户端，加上自己的帧缓冲。
- 半截 UTF-8 和被拆开的帧会在 TCP 上分开到达。解析器要攒到空行才交出一条事件。
- 流在没有终态时断开，不是成功。客户端保留已折进去的内容，并记下最后的 `seq`。
- 停止按钮如果只中止本地连接，服务端的循环还在跑。重连会把用户以为停掉的回答又接回来。
- 页面卸载、终端被关掉、网络抖动，服务端分不清是停止还是断线。停止必须走 `POST /cancel`。
- CLI 和 Web 如果各写一套事件含义，同一条 `tool.result` 会在两边拼出不同的对话。

## 设计

### 两边共用

| 步骤 | 做法 |
| --- | --- |
| 创建 | `POST /v1/threads/{thread_id}/runs`，正文是用户消息，`Accept: text/event-stream`。可选 `Idempotency-Key` |
| 身份 | 立刻读响应头 `X-Run-Id`。第一条 `run.started` 再核对一次 |
| 阅读 | 按 `seq` 调用和 Store 相同的 `reduce`。心跳帧丢掉 |
| 结束 | 收到 `run.completed`、`run.failed` 或 `run.cancelled` 后停止阅读 |
| 未完成 | 连接在终态之前断开：界面保持已有文字，状态标成未完成 |
| 停止 | 先 `POST /v1/runs/{run_id}/cancel`，再中止本地读取 |
| 断线 | 只中止本地读取，不调用取消。记下 `seq` |
| 再订 | 第 10 步用 `GET /v1/runs/{run_id}/events?since=`。先订上实时尾部，再按序号补洞，重复序号丢掉。游标落在窗口外就改取快照 |

响应头之前的 400 和 409 是普通 HTTP 错误，不进入 `reduce`。409 里带有已经在跑的 `run_id`，客户端改去看那一次，不再开一条新的。接口见 `docs/08-创建运行与取消接口设计.md`。帧的拆法见 `docs/03-SSE设计.md`。

第 8 步先把正在看的这一条流做完。刷新之后的补洞依赖第 10 步的 GET。在那之前，刷新会失去还没画完的增量，服务端的 run 仍继续写内存日志。

### CLI 和 Web 分开的部分

| | CLI | Web |
| --- | --- | --- |
| 传输 | `httpx` 流式读取，可以带任意头 | `fetch` + `ReadableStream`。不用 `EventSource` 创建运行 |
| 停止键 | `Ctrl+C` 视为停止：先取消，再退出 | 停止按钮先取消，再 `abort` 这次 `fetch`。`pagehide`、路由卸载、组件卸载只中止 `fetch` |
| 呈现 | 工具行、正文、错误依次打到终端。增量可以直接打出 | 同一份 `View` 画成气泡和工具卡片。流式 Markdown 要容忍没闭合的代码块 |
| 重绘 | 第一版逐段打印。完整 TUI 再按帧合并增量，避免每次 token 都重画整屏 | 按 `message_id` 和 `call_id` 更新对应节点，不整页替换 |
| 多开 | 一个进程看一次 run | 多个标签可以看同一次 run。任一标签的停止会取消这整次 run |
| 机器可读 | 以后可以加 JSONL：进度打到 stderr，最终结果打到 stdout。第 8 步只做给人看的文本 | 不需要这套分流 |

CLI 进程崩溃不应带走服务端的 run。阅读进程和循环本来就是分开的。终端被直接杀掉时来不及发取消，这次 run 会继续，和刷新页面一样。

Web 在用户按过停止之后，不要自动再订这次 run。否则会接到一条正在取消的流上，界面在半截回答和终态之间闪一下。下一次发送是新的 `run_id`。

## 实现方式

解码和 `reduce` 放在 `app/sse/` 和 `app/events/` 里，CLI 直接引用。Web 若是另一门语言，就按 `docs/03-SSE设计.md` 和 `docs/02-RunEvent设计.md` 做同一套行为，不另定事件含义。

CLI 放在 `cli/`。`cli/present.py` 的 `format_view` 已经负责把 `View` 打成文本：先工具行，再消息，再错误。第 8 步补上发起 POST、读流、折进 `View`，以及把 `Ctrl+C` 变成取消。

Web 后做。页面只持有 `threadId`、`runId`、`lastSeq` 和 `View`。创建、停止、再订都调用上面的命令，组件不自己解释 SSE。

第 8 步的完成标准是：CLI 能看完一次天气式运行，停止键会让服务端写下 `run.cancelled`，中途断开进程不会。Web 用同一条流把文字和工具画出来，停止和离开页面走两条路径。

## 代码

阅读循环两边相同。呈现函数换成终端打印或页面更新即可。

```python
async def watch_run(thread_id: str, message: str):
    view = empty_view()
    async with client.stream("POST", f"/v1/threads/{thread_id}/runs", json={"message": message}) as response:
        if response.status_code == 409:
            return view
        response.raise_for_status()
        run_id = response.headers["X-Run-Id"]
        decoder = FrameDecoder()
        async for chunk in response.aiter_bytes():
            for event in decoder.feed(chunk):
                view = reduce(view, event)
                render(view)
                if event.type in {"run.completed", "run.failed", "run.cancelled"}:
                    return view
        return view
```

停止和断线分开。

```python
async def stop(run_id: str, reader):
    await client.post(f"/v1/runs/{run_id}/cancel")
    reader.cancel()

def on_page_leave(reader):
    reader.cancel()
```

对应关系：

- `FrameDecoder` 负责半截帧。`reduce` 负责把 `message.delta` 和 `tool.result` 拼进 `View`。`render` 只看 `View`。
- `X-Run-Id` 一到就可以停止，不必等第一条事件。
- `watch_run` 在终态返回。流提前结束时，`View` 里已有的文字保留，调用方把它标成未完成。
- Web 的离开页面走 `on_page_leave`。只有停止按钮走 `stop`。CLI 的 `Ctrl+C` 走 `stop`，进程被杀掉则来不及取消。
