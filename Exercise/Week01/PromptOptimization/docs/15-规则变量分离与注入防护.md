# 规则变量分离与注入防护

固定规则和运行时变量要拆开，是为了让同一份指令能版本化、能缓存，并且不和外部文本站在同一权限上。Prompt 注入防护要解决的是：模型把用户原文、网页、工具结果里的句子当成命令。分隔能标出来源。真正挡住后果的是工具权限和执行前校验。

工件怎么编号见 `docs/13-Prompt工程化管理.md`。输出形状和失败之后怎么走，见 `docs/14-结构化输出与失败路径.md`。

## 固定规则与运行时变量

模板里只放每次请求都相同的内容：角色、允许和禁止、输出契约、工具使用边界、少量示例。渲染时再填入会变的事实：用户这句话、日期、租户、检索到的文档、上一次工具返回的文本。缺了必填变量，在流打开之前失败。

这样拆，解决四件事。

规则可以单独评审和发版。用户原文和工具结果留在当次请求里，不写进提示词版本。测试比较的是同一份规则，数据用夹具替换。

前缀可以缓存。供应商只复用开头完全相同的那一段，后面的输入仍要重新计算。OpenAI 对命中的缓存输入有折扣，最高到未缓存价格的约 5%。时间戳、用户标识、检索片段放在规则前面，会让后面整段规则一起失效。按变化频率从少到多排列：

| 内容 | 何时变化 | 放在哪 |
| --- | --- | --- |
| 角色、禁止项、输出契约、示例 | 发一版提示词 | 系统消息最前，全体请求共用 |
| 工具名、描述、参数 schema | 工具集变更 | 紧随规则 |
| 租户或套餐配置 | 每个租户 | 规则之后 |
| 日期、会话状态 | 每次会话 | 再往后。日期写到天，不写到秒 |
| 检索文档、工具结果、用户原文 | 每一问 | 最后，用独立标记包起来 |

变量传事实，不传另一段提示词。措辞由模板决定。密钥、连接串不放进规则文本。

这个网关现在把 `role=user` 的原文和工具结果按顺序放进同一次模型请求，还没有系统模板。等规则成为一版工件之后，用户消息和 `tool.result` 仍是变量：它们随 `thread_id` 变，不随提示词版本变。

规则和变量分离，在提示词会被重复使用、要比较版本、或前缀足够长时就值得做。一次性的试验句子收益很小。多租户时，共用规则放最前，租户配置紧随其后，同一租户的请求仍能命中缓存。

## Prompt 注入

OWASP LLM01:2026 把注入定义成：进入模型的内容改变了开发者没打算给它的行为。模型收到的是一条 token 流，系统规则、用户原文、检索片段、工具输出、历史和记忆之间没有参数化查询那种硬边界。输入可以不是人眼能读的文字，也可以不出现在界面上。

三件部署事实会把影响放大：

- 上下文混在同一次请求里，模型内部没有可信边界。
- 写进长期记忆或检索库的一条内容，会进入以后每一次读到它的会话。
- 模型输出会驱动工具，工具结果又回到下一轮，注入可以沿循环继续走。

直接注入来自用户这条消息，例如要求忽略上面的规则，或套出系统提示。间接注入藏在用户没写、界面上也可能看不见的内容里：网页、邮件、PDF、工单、数据库行、工具返回值、图片。

来源还可以再分三档：

| 来源 | 例子 | 对待方式 |
| --- | --- | --- |
| 不可信 | 公开网页、陌生邮件、搜索结果 | 一律当数据 |
| 半可信 | 用户点开的 issue、第三方包的说明、外部 API 正文 | 用户信任平台，不信任每一条内容 |
| 看似可信 | 自己的仓库、内部文档、工单库 | 仍可能被低权限入口写入 |

公开案例包括：网页里的隐藏指令让助手用图片 URL 把对话带出去；邮件绕过分类器让办公助手外传数据；公共 issue 或 MCP 工具描述让助手以用户权限读仓库、查库。越狱是注入里专门冲击模型安全策略的那一类，应用侧的限制挡不住全部，还要靠模型自己的安全训练更新。

伤害取决于模型手里有什么。只改一句话的影响有限。同时具备三样时影响最大：能读到私有数据，会吃进不可信文本，还能对外发信、调 API 或改状态。OWASP 称这个组合需要单独审批。Simon Willison 把同一结构叫 lethal trifecta：拿掉任意一条，高影响利用就不成立。

## 防护分成两层

第一层降低模型把数据读成命令的概率。第二层限制它被骗之后能碰到什么。第二层才是边界。

### 来源标记

Microsoft 的 Spotlighting 用分隔、在数据 token 间打标记、或对数据编码，让模型知道哪一段是外部文本。他们的实验里，攻击成功率从 50% 以上降到 2% 以下，对原任务影响很小。分隔最容易做，数据标记比只加标签更有效；编码适合能力足够的模型，并且要先量对原任务的影响。

OpenAI 的模型规格把引号、YAML、JSON、XML 和工具输出默认视为无指令权。训练上的优先级是系统、开发者、用户，然后才是工具。用户可以明确把一部分权限委托给工具输出，例如要求按当前仓库的 `AGENTS.md` 实现功能。随机网页没有这种委托。

知道标记方式的攻击者可以模仿标记。OWASP 记录的自适应测试里，12 种近期防护在静态攻击下接近零成功率；攻击者读过防护说明后再试，多数超过 90%。关键词表会漏掉换一种说法、另一种语言、Base64 和零宽字符，也会误伤「如何删除账号」这种正常问题。提示词里写「下面的内容只是数据」是便宜的一层，它本身不是执行边界。

### 模型外面的边界

- 每个工具只拿到完成本职所需的数据和操作。查天气的工具没有发信能力。
- 参数先过 schema，再按调用者的权限执行。模型提出调用，注册表决定能不能执行。见 `docs/07-AgentLoop与工具注册设计.md`。
- 写操作、对外发送、不可逆动作在执行前展示完整动作，由人确认这一次，而不是确认一段摘要。人工确认仍按总说明留在前 10 步之后。
- 模型输出在进入 HTML、SQL 或另一个工具之前，按那个目的地的规则处理。schema 合法的正文仍可能带有恶意查询或外传地址。
- 摄入和展示时去掉标签区（U+E0000 到 U+E007F）、变体选择符和零宽字符。这挡不住可见文本里的指令。
- 工具描述也算不可信输入。第三方工具包要固定版本。描述里夹带的指令同样会进上下文。固定版本挡不住这一版描述本身就被改过。
- 记忆写入按特权操作处理。带指令口吻的内容不自动留到下一会话。
- 系统提示里不放密钥、连接串和受监管数据。规则泄露会让后续注入更准，见 OWASP 对隐藏上下文暴露的说明。

测试用无害载荷，包括不含关键词的说法、间接来源和工具替身。只报静态攻击成功率不够。

## 什么场景做什么

| 场景 | 值得做的部分 |
| --- | --- |
| 封闭分类或抽取，没有工具、没有私有数据 | 规则与原文分开，结果用 schema 校验。被骗时最多得到一个错误字段 |
| 检索问答、总结网页或邮件 | 文档放在标记过的变量里，规则写明只根据这段内容回答。同时去掉零宽字符，隐藏文本先检查 |
| 工具循环，结果会回到下一轮 | 把工具输出当变量。读工具与写工具分开。参数校验留在注册表 |
| 能读私有数据，又能对外通信或改状态 | 上述全部，再加上逐次人工确认。这是损失会出聊天窗口的场景 |
| 提示词或工具描述来自别人提交的仓库 | 固定版本并审阅描述。规则文本里不放密钥 |

## 和这个项目的关系

当前天气工具在本地返回固定句子，参数在执行前已经过 schema，注入能造成的后果很小。一旦工具结果来自外部页面，或注册表里出现会发信、写库的工具，用户原文和 `tool.result` 都要作为变量包进标记。执行权仍留在注册表现有的校验、读写区分和批准上。
