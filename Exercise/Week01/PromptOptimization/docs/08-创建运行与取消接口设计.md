# 创建运行与取消接口

创建、取消、状态查询和断线再订是四条职责不同的接口。第 7 步做创建、取消和状态查询。按序号补事件在第 10 步，路由已经接上。创建负责开工并交出这条 run 的事件流。取消只在运行记录上设置标记。关掉页面只是没人在看。

依据：

- [AG-UI：HTTP 与 SSE](https://docs.ag-ui.com/spec/1.0/basic/transports/http-sse)
- [LangGraph：创建、加入和取消](https://docs.langchain.com/langsmith/agent-server-api/thread-runs/create-run-stream-output)
- [LingxiGraph：幂等与 SSE 恢复](https://docs.lingxilearn.cn/docs/en/api/errors-events/)
- [Hercules：线程忙与 run_id](https://hercules.app/docs/agents/api-reference)
- [Ably：停止和断线](https://ably.com/blog/stop-vs-disconnect-canceling-ai-streaming)

## 概念

| 接口 | 何时做 | 作用 |
| --- | --- | --- |
| `POST /v1/threads/{thread_id}/runs` | 第 7 步 | 在这段对话里新建一次 run，响应体就是它的 SSE |
| `POST /v1/runs/{run_id}/cancel` | 第 7 步 | 只设置这次 run 的取消标记 |
| `GET /v1/runs/{run_id}` | 第 7 步 | 读状态和最新序号，不读事件流 |
| `GET /v1/runs/{run_id}/events?since=` | 已实现 | 断线后从序号之后把日志补上，并接上仍在发生的事件 |

`thread_id` 在创建路径里。服务端分配 `run_id`，放进响应头 `X-Run-Id` 和第一条 `run.started`。客户端不必等解析完第一帧才能取消。

浏览器的 `EventSource` 只能发 GET，带不了 JSON 正文和自定义鉴权头。创建用 `fetch` 读 `ReadableStream`。第 10 步的 GET 才适合 `EventSource` 和 `Last-Event-ID`。帧格式见 `docs/03-SSE设计.md`。事件字段见 `docs/02-RunEvent设计.md`。

## 它解决什么

- 创建如果先把整次运行跑完再返回，客户端在第一个 token 之前不知道连接是否还活着。校验通过就要交出响应头，事件随后逐条写。
- HTTP 200 只表示流打开了。参数错误、线程正忙，必须在响应头之前用状态码拒绝。
- 用户按停止和网络断开，在 TCP 上看起来一样。只根据连接关闭来停模型，会把一次刷新当成取消，也会在用户真的按了停止时停不下来。
- 客户端超时后重试同一次 POST，会开出两条 run，工具可能执行两遍。
- 取消按钮点了两次，或者取消请求比循环写终态更早到达，接口都要给出稳定结果，不能再追加第二条 `run.cancelled`。

## 设计

### 创建

请求体是 JSON，至少包含这一问的用户消息。`Content-Type: application/json`，`Accept: text/event-stream`。可选 `Idempotency-Key`。也可以带 `prompt`（`name` 和 `version`）和 `variables`。不带 `prompt` 时用当前指针指向的版本。相同的键、相同的消息、相同的版本和变量返回已经创建的那次 run 的事件流，不再新建。键相同、这些内容不同，返回 409。

响应头发出之前就可以拒绝：

| 状态 | 何时 |
| --- | --- |
| 400 | 正文不是合法 JSON，缺少用户消息，提示词版本不存在，变量缺失、多余或模板拼不出来，或版本里的工具没有注册 |
| 409 | 这个线程上已经有一次未结束的 run。响应里带上那个 `run_id` |
| 401 / 403 | 鉴权失败。第一版还没有鉴权时可以不返回这两项 |

一个线程同时只跑一次 run。上一次已经 `completed`、`failed` 或 `cancelled` 之后，下一次 POST 再建新的 `run_id`。

通过校验之后：

1. 去掉用户消息里的标签字符、变体选择符和零宽字符，再写入线程并创建 run。只剩这些字符时仍按缺少用户消息拒绝。状态查询不因此增加字段。记录先是 `queued`，循环写入 `run.started` 后才成为 `running`。创建接口不提前改这个状态。
2. 把 `execute_run` 放到独立任务里。它继续写 Store，不靠这条 HTTP 连接活着。
3. 写出响应头并立刻刷新：`Content-Type: text/event-stream`、`Cache-Control: no-cache, no-transform`、`X-Accel-Buffering: no`、`X-Run-Id`。
4. 从 `seq` 0 订阅 Store，把新事件编码成 SSE，直到终态事件。心跳由 `sse/` 按间隔写入，不进 Store。

客户端断开时，只结束这次编码。任务继续跑。这和 LangGraph 流式创建的默认 `on_disconnect: continue` 一致。AG-UI 的基础绑定不恢复断线，断了就用新的 `runId` 再跑。本项目要续传，所以断线不取消。

响应头已经发出去之后，运行失败只写成 `run.failed`。流在没有终态事件时被掐断，客户端把它当成未完成，记下最后的 `seq`。

### 取消

`POST /v1/runs/{run_id}/cancel` 没有事件流。它只调用 Store 的 `request_cancel`。循环在下一步边界看见标记，停掉上游模型，必要时等当前工具返回，再追加 `run.cancelled`。循环的约定见 `docs/07-AgentLoop与工具注册设计.md`。

接口自己不等循环写完终态。返回表示标记已经设上。原来那条 SSE 若还连着，会随后收到 `run.cancelled`。

| 状态 | 何时 | 正文 |
| --- | --- | --- |
| 202 | 标记刚刚设上，或已设上但循环还没写终态 | `run_id`，状态 `cancelling` |
| 200 | 这次 run 已经是 `cancelled` | `run_id`，状态 `cancelled` |
| 409 | 已经是 `completed` 或 `failed` | 当前状态 |
| 404 | 没有这个 `run_id` | 错误说明 |

重复取消是安全的。第二次仍返回 202 或 200，不再写第二条终态事件。取消不携带新的用户消息，也不删除线程上已经写下的消息和工具结果。

### 状态与再订

两条 GET 不能合成一条。状态查询回答「还在跑吗」。再订把断掉的事件补回来。创建用的 POST 已经在推实时 SSE，它也代替不了这两条 GET：连接一断，客户端就不再有这条流。

`GET /v1/runs/{run_id}` 在第 7 步就要有。Store 的 `since` 只让本进程里的测试按序号读日志，它不是 HTTP 接口，既不能回答状态，也不能给客户端补事件。

这一条返回 `run_id`、`thread_id`、状态、最新 `seq`，以及这次 run 绑定的 `prompt_name`、`prompt_version`、`prompt_hash`。没有绑定提示词时后三个字段为空。另外返回 `degraded` 和 `degrade_reason`：最终答案没能通过输出契约、改成带标记的普通文字时，`degraded` 为真，原因写在 `degrade_reason`；没有降级时分别是 `false` 和 `null`。未知 `run_id` 返回 404。状态就是 Store 里的状态，取消标记已经设上但循环还没写终态时，这里仍是 `queued` 或 `running`，不是取消接口里的 `cancelling`。它不返回事件，也不打开 SSE，也不返回提示词正文或没通过校验的 JSON。终态之后，界面上的文字仍以日志或线程里的最终消息为准。

`GET /v1/runs/{run_id}/events?since=` 已经接上。查询是 `seq > since`。`since` 缺省为 0，负数返回 400。游标小于该 run 的最小保留序号时返回 JSON `409`，正文含 `gap`、`thread_id`、`min_seq`，不把后面的事件充作这段缺口。内存 Store 的最小序号一直是 0，所以不会返回缺口。这条 GET 不创建 run，断开也不取消运行。Store 的读取约定见 `docs/06-RunStore设计.md`。

## 实现方式

创建、取消和状态查询放在 `app/api/`。回放是第四条路由，`create_router(store)` 一起注册，并持有同一个 Store。循环任务用 `asyncio.create_task` 启动，保存在应用状态里，避免被提前回收。

创建处理函数在写响应头之前不做模型调用。订阅用 Store 已有的 `since`：先把大于游标的事件编码出去，再等待通知，醒来后仍以 `since` 的结果为准。编码、心跳和响应头沿用 `docs/03-SSE设计.md`。终态事件发出后关闭响应体。

客户端保存 `X-Run-Id` 和最后一条事件的 `seq`。停止按钮调用取消接口。刷新之后可以用状态 GET 看这次 run 还在不在跑，并用 `GET /v1/runs/{run_id}/events?since=` 把没画完的增量补回来。

这四条路由和「线程上是否已有未结束 run」的查询都在 `app/api/routes.py`。内存 Store 和 SQLite Store 用同一组方法。回放路由按序号补事件。

## 代码

创建把开工和观看拆开。观看结束不影响开工。

```python
@router.post("/v1/threads/{thread_id}/runs")
async def create_run(thread_id: str, body: RunInput, request: Request):
    if not body.message.strip():
        raise HTTPException(400, "缺少用户消息")
    active = store.active_run(thread_id)
    if active is not None:
        raise HTTPException(409, detail={"run_id": active.run_id})
    store.add_message(thread_id, "user", body.message)
    run = store.create_run(thread_id, new_run_id())
    asyncio.create_task(execute_run(store, model, tools, run.run_id))
    return StreamingResponse(
        watch(store, run.run_id, request),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache, no-transform",
            "X-Accel-Buffering": "no",
            "X-Run-Id": run.run_id,
        },
    )

async def watch(store, run_id: str, request: Request):
    seq = 0
    while True:
        if await request.is_disconnected():
            return
        for event in store.since(run_id, seq):
            seq = event.seq
            yield encode(event)
            if event.type in {"run.completed", "run.failed", "run.cancelled"}:
                return
        await store.wait_for_change()
```

取消只改标记。终态仍由循环写入。

```python
@router.post("/v1/runs/{run_id}/cancel")
async def cancel_run(run_id: str):
    try:
        run = store.get_run(run_id)
    except KeyError:
        raise HTTPException(404, "未知运行")
    if run.status in {"completed", "failed"}:
        raise HTTPException(409, detail={"run_id": run_id, "status": run.status})
    if run.status == "cancelled":
        return {"run_id": run_id, "status": "cancelled"}
    store.request_cancel(run_id)
    return JSONResponse({"run_id": run_id, "status": "cancelling"}, status_code=202)
```

状态查询是普通 JSON，没有事件流。

```python
@router.get("/v1/runs/{run_id}")
async def get_run(run_id: str):
    try:
        run = store.get_run(run_id)
    except KeyError:
        raise HTTPException(404, "未知运行")
    return {
        "run_id": run.run_id,
        "thread_id": run.thread_id,
        "status": run.status,
        "seq": run.seq,
        "prompt_name": run.prompt_name,
        "prompt_version": run.prompt_version,
        "prompt_hash": run.prompt_hash,
        "degraded": run.degraded,
        "degrade_reason": run.degrade_reason,
    }
```

对应关系：

- 400 和 409 发生在 `StreamingResponse` 之前，客户端拿到的是普通 HTTP 错误，没有 SSE。
- `create_task` 让循环独立于 `watch`。`watch` 在连接断开时返回，不调用 `request_cancel`。
- `watch` 用 `since` 的严格大于接着上次的 `seq`，并把终态当作这条响应的结尾。
- 取消接口的 202 只表示标记已设置。`run.cancelled` 要等原来的 SSE 或以后的 `since` 才能看见。
